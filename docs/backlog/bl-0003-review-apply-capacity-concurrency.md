# 정원 초과와 중복 신청 경쟁 조건 점검

- **ID:** BL-0003
- **기록일:** 2026-08-16

## 배경

선착순 신청은 여러 사용자가 동시에 요청할 수 있는 기능이다. 이 도메인에서는 정원보다 많은 신청이 저장되거나, 중복 신청이 허용되지 않는 이벤트에서 같은 사용자가 중복으로 신청되는 상황을 막아야 한다.

현재 코드에는 DB 기반 신청 처리와 Redis 카운터 기반 신청 처리 흐름이 함께 존재한다. 보안 점검 과정에서 두 흐름이 동시 요청 상황에서 같은 불변식을 지키는지, 애플리케이션 락과 DB unique constraint가 서로 충분히 보완되는지 확인할 필요가 발견되었다.

## 목표

동시 신청 상황에서 정원 초과, 중복 신청, 캐시 카운터와 DB 저장 상태 불일치 같은 경쟁 조건 위험을 점검한다. 여러 요청이 동시에 들어와도 선착순 정원과 중복 신청 정책이 유지되는지 확인하고, Redis 기반 흐름과 DB 기반 흐름의 차이를 명확히 파악한다.

# PD-0004: 신청 후 추가 정보

- **날짜:** 2026-08-17
- **대체:** 해당 없음
- **대체됨:** 해당 없음

## 배경과 문제

이벤트마다 참가자에게 받아야 할 추가 정보가 다르다. 신청하지 않은 사용자가 정보를 조회·저장하거나, 최초 입력과 수정의 경계를 구분하지 않으면 참가자 정보의 소유 관계와 완료 상태가 불명확해진다.

## 목표

신청이 확정된 회원만 해당 이벤트가 요구하는 정보를 한 번 생성하고 이후 수정할 수 있게 하며, 필수 정보가 비어 있는 완료 상태를 막는다.

## 정책

- **PD-0004-R1:** 이벤트별 추가 정보 항목은 이벤트를 만들 때 선택하며, 참가자에게는 해당 이벤트가 요구하는 항목만 제공한다.
- **PD-0004-R2:** 이벤트 신청이 확정된 회원만 자신의 추가 정보 항목과 저장 결과를 조회하거나 입력·수정할 수 있다.
- **PD-0004-R3:** 회원과 이벤트의 조합에는 하나의 추가 정보 묶음만 존재한다.
- **PD-0004-R4:** 최초 입력은 아직 추가 정보가 없을 때만 성공한다. 이미 입력한 상태에서 다시 최초 입력을 요청하면 기존 정보를 중복 생성하지 않는다.
- **PD-0004-R5:** 수정은 기존 추가 정보가 있을 때만 성공하며, 저장된 값을 제출한 최신 값으로 바꾼다.
- **PD-0004-R6:** 필수 항목은 공백을 제외한 값이 하나 이상 있어야 완료할 수 있다. 선택 항목은 빈 값일 수 있다.
- **PD-0004-R7:** 이벤트에 추가 정보 항목이 없으면 빈 정보 묶음으로 정보 입력 단계를 완료할 수 있다.
- **PD-0004-R8:** 신청 확정과 추가 정보 완료는 별도 상태이므로, 정보가 없다는 사실만으로 이미 확정된 신청을 취소하거나 실패로 바꾸지 않는다.

## 거절하는 시나리오

- 신청하지 않은 회원이 이벤트의 추가 정보 항목이나 저장 결과에 접근한다.
- 이미 추가 정보가 있는데 최초 입력으로 두 번째 정보 묶음을 만든다.
- 추가 정보가 없는데 수정 요청을 보낸다.
- 필수 항목을 빈 값으로 제출해 완료한다.

## 허용하는 시나리오

- 신청 직후 추가 정보를 나중에 입력하기 위해 신청 완료 상태만 유지한다.
- 이미 입력한 추가 정보를 다시 불러와 수정한다.
- 선택 항목을 비워 둔 채 필수 항목만 입력한다.

## 정책이 정하지 않는 것

- 항목 종류별 화면 컴포넌트와 입력 위젯
- 추가 정보의 영속화 구조

## 미결

- 제출 항목이 실제로 해당 이벤트에 속하는지, 필수 항목이 요청에서 통째로 빠졌는지, 선택 값이 허용된 도메인과 형식을 지키는지에 대한 서버 검증 범위가 확정되어 있지 않다.

# PD-0005: 외부 사용자 인증 세션

- **날짜:** 2026-08-17
- **대체:** 해당 없음
- **대체됨:** 해당 없음

## 배경과 문제

외부 사용자는 별도 회원 서비스에서 로그인하거나 가입한 뒤 Catching으로 돌아온다. 인증 요청과 콜백의 연결을 검증하지 않거나 같은 콜백 상태를 반복 사용할 수 있으면 다른 인증 흐름의 결과가 현재 브라우저 세션에 섞일 수 있다.

## 목표

로그인·회원가입 요청과 콜백을 짧게 유지되는 일회성 상태로 연결하고, 인증된 회원만 개인별 기능을 사용하게 한다.

## 정책

- **PD-0005-R1:** 외부 사용자는 로그인과 회원가입 중 목적을 선택해 회원 서비스의 인증 화면으로 이동할 수 있다.
- **PD-0005-R2:** 인증을 시작할 때마다 새로운 브라우저 세션과 예측하기 어려운 상태 값을 만들며, 둘의 유효 시간은 10분이다.
- **PD-0005-R3:** 인증 세션 식별자는 브라우저 스크립트에서 읽을 수 없고 보안 연결에서만 전송되며, 동일 사이트 수준의 콜백 흐름에 사용한다.
- **PD-0005-R4:** 인증 코드 교환은 현재 브라우저 세션에 저장된 상태와 콜백 상태가 정확히 일치할 때만 허용한다. 상태가 없거나 다르면 요청을 거절한다.
- **PD-0005-R5:** 인증 코드 교환에 성공하면 사용한 세션 상태를 즉시 폐기한다. 같은 세션 상태는 다시 사용할 수 없다.
- **PD-0005-R6:** 회원별 신청, 약관 동의와 추가 정보 기능은 유효한 액세스 토큰으로 확인된 회원에게만 제공한다.
- **PD-0005-R7:** 액세스 토큰이 만료되면 갱신 토큰으로 한 번 갱신한 뒤 원래 요청을 다시 시도한다. 갱신에 실패하면 저장된 로그인 정보를 제거하고 비로그인 상태로 전환한다.

## 거절하는 시나리오

- 인증을 시작한 브라우저 세션이 없는데 인증 코드를 교환한다.
- 콜백 상태가 현재 세션의 상태와 다르다.
- 이미 성공적으로 사용한 세션 상태로 다시 코드를 교환한다.
- 인증되지 않은 사용자가 회원별 기능을 호출한다.

## 허용하는 시나리오

- 같은 인증 진입점에서 로그인 또는 회원가입을 선택한다.
- 만료된 액세스 토큰을 갱신하고 원래 요청을 한 번 재시도한다.

## 정책이 정하지 않는 것

- 회원 서비스 내부의 로그인·가입 방식
- 토큰의 발급 형식과 암호화 방식

## 미결

- 갱신 토큰을 브라우저의 어느 저장소에 둘지는 보안 위험 검토 후 별도 결정이 필요하다.

## 선착순 시스템

마라톤,예매,식당 예약 등 여러가지 선착순으로 운영되는 시스템이 필요한 서비스의 경우
우리 시스템을 통해서 선착순으로 신청한 사람들의 정보를 제공한다.

## 고객 어드민

- 어드민에서 선착순 이벤트를 등록한다.
    - 선착순 이벤트 이름
    - 선착순 이벤트 참가 수(제한 수)
    - 상태
    - 선착순 신청 일시
    - 선착순 종료 일시
    - 노출 일시
    - 신청 조건
    - 중복 신청 여부
    - 운영하는 회사,주관
    - 참가 방식
        - 리다이렉트
        - API
    - 예비 번호
        - 예비 번호 여부
        - 예비 번호 최대 인원
    - 자리가 남게되는 경우 정책
        - 예비번호를 받은 사람이 우선권을 가짐
        - 자리가 남은 후 먼저 신청한 사람이 우선권을 가짐

## 서비스

- 등록된 선착순 이벤트를 보여줄 수 있어야한다.
- 선착순 이벤트 일시가 된 경우 신청할 수 있어야한다.
- 선착순 이벤트를 신청하면 몇번째인지 알려줄 수 있어야한다.
- 신청 후 참가 거절을 할 수 있어야한다.
    - 제한 시간내 등록하지 않은 경우
    - 수동으로 포기한경우
- 참가 가능한 사람이 거절한 경우 참가 신청은 안됬지만 예비번호를 받은 사람이 우선권을 갖는다.

### 추가로 꼭 검토할 것

- 신청과 확정의 구분
- 대기열 최대 인원
- 결원 발생 시 자동 승급 여부
- 중복 신청 가능 여부
- 신청 자격 조건
- 외부 연동 실패 처리
- 선착순 판단 기준 시각/순번

## mvp v0

- 어드민에서 선착순 이벤트를 만들 수 있어야한다.
    - 이름,참가 수,상태,일시,주관,신청 성공시 참가,예비번호부여,최대인원은 없음,예비번호 우선권을 가짐.
    - 만든 직후 선착순 이벤트는 운영될 수 없는 CREATED 상태이며 승인을 받아야 READY 상태로 변경된다.
    - READY 상태이면서 displayAt 이 도달한 이벤트의 경우에 ON_GOING 상태의 이벤트가 된다.
    - endAt 이후에는 END 상태의 이벤트가 된다.
- 외부망으로 제공하는 API에서 등록한 선착순 이벤트를 조회할 수 있어야한다.
    - 현재 시각이 노출일시보다 같거나 큰 경우 노출될 수 있어야한다.

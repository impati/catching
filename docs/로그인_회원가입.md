## 로그인 흐름

1. 사용자가 catching 프론트에서 로그인 클릭
2. 프론트가 GET /v1/auth/gateway?mode=login 호출
3. external이 설정된 web-redirect-url을 기준으로 회원 웹 URL을 만들어 반환
4. 브라우저가 회원 웹으로 이동
5. 회원 웹이 clientId, redirectUrl 검증 후 이메일/비밀번호 로그인 처리
6. 로그인 성공 시 회원 웹이 redirectUrl?code=...&clientId=...로 돌려보냄
7. catching 프론트가 code를 읽어 POST /v1/auth/code 호출
8. external이 회원 서버에 code를 전달해 accessToken, refreshToken으로 교환
9. 프론트가 accessToken으로 GET /v1/auth/me 호출
10. memberId, nickName을 받아 로그인 사용자로 표시

## 회원가입 흐름

1. 사용자가 catching 프론트에서 회원가입 클릭
2. 프론트가 GET /v1/auth/gateway?mode=signup 호출
3. 회원 웹이 회원가입 화면으로 열림
4. 회원 웹에서 이메일 인증, 인증 확인, 회원가입 API를 순서대로 처리
5. 가입이 끝나면 같은 계정으로 client login을 호출해 authorization code 발급
6. 이후는 로그인과 동일하게 redirectUrl?code=...&clientId=...로 돌아옴
7. catching이 code를 token으로 교환
8. accessToken으로 /v1/auth/me 조회
9. memberId, nickName을 catching 서비스 사용자 식별 정보로 사용 가능해짐
